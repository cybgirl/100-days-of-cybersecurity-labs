# Day 29 – Creating Snort Local Rules & Traffic Analysis 🛡️📡

## 🧠 Overview
Today’s lab focused on **creating custom Snort local rules** to generate live alerts and test Snort’s detection capabilities. I simulated real-world traffic using Kali Linux and Metasploit within a local network environment.

This hands-on session strengthened my understanding of **rule creation, traffic analysis, and real-time threat detection**.

---

## 🎯 Objectives
- Create custom Snort local rules  
- Generate live network traffic for testing  
- Detect ICMP, FTP, and SSH activities  
- Analyze Snort alerts and logs  
- Use Wireshark for packet investigation  

---

## 🛠️ Snort Rule Creation & Traffic Simulation

- Configured Snort to alert on **ICMP (ping) traffic** to detect network scanning  
- Created rules for **FTP and SSH login activity**  
- Simulated traffic using **Kali Linux and Metasploit**  
- Observed how Snort detects and alerts on suspicious behavior in real time  
- Used **Snorpy** (GUI-based rule generator) to simplify rule creation  

---

## 📌 Working with Snort Community Rules

- Explored **Snort community rules** for predefined threat detection  
- Tested rule sets against simulated vulnerabilities  
- Learned the importance of:
  - Updating rules regularly  
  - Customizing rules for specific environments  

---

## 📊 Logs & Traffic Analysis

- Analyzed **Snort alert logs** to understand detection behavior  
- Used **Wireshark** to:
  - Capture network traffic  
  - Inspect packets  
  - Identify suspicious patterns  

---

## 🔎 Security Insight
- Custom rules improve detection accuracy  
- Real traffic testing validates IDS effectiveness  
- Log analysis is essential for incident response  
- Combining Snort with Wireshark enhances visibility

## 🚀 Key Takeaways
